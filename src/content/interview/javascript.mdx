## 변수와 타입

**Q. (단골) var, let, const의 차이는 무엇인가요?**

**A.** `var`는 **함수 스코프**이고 같은 이름으로 재선언이 가능하며, 호이스팅 시 `undefined`로 초기화됩니다. `let`과 `const`는 **블록 스코프**이고 재선언이 불가능하며, 호이스팅은 되지만 선언문 전까지 **TDZ(Temporal Dead Zone)** 에 있어 접근하면 `ReferenceError`가 납니다. `const`는 **재할당이 불가능**할 뿐 객체 내부 값의 변경까지 막지는 않습니다. 실무에서는 기본적으로 `const`를 쓰고, 재할당이 필요할 때만 `let`을 쓰며 `var`는 사용하지 않습니다.

```js
console.log(a); // undefined
var a = 1;
console.log(b); // ReferenceError (TDZ)
let b = 2;
```

**Q. (단골) 호이스팅(Hoisting)이란 무엇인가요?**

**A.** 호이스팅은 코드 실행 전 **실행 컨텍스트 생성 단계**에서 변수와 함수 선언이 먼저 메모리에 등록되어, 마치 선언이 스코프 최상단으로 끌어올려진 것처럼 동작하는 현상입니다. 실제로 코드가 이동하는 것이 아니라 **렉시컬 환경에 식별자가 미리 기록**되는 것입니다. **함수 선언문**은 함수 전체가 호이스팅되어 선언 전에 호출할 수 있지만, **함수 표현식**은 변수 규칙을 따릅니다. `var`는 `undefined`로 초기화되고, `let`/`const`/`class`는 초기화되지 않아 TDZ에 놓입니다.

> **꼬리 질문**: 함수 선언문과 함수 표현식의 차이는? / 호이스팅을 실행 컨텍스트 관점에서 설명해보세요.

**Q. JavaScript의 데이터 타입에는 무엇이 있나요?**

**A.** **원시 타입(Primitive)** 7가지 — `string`, `number`, `bigint`, `boolean`, `undefined`, `null`, `symbol` — 과 **객체 타입(Object)** 으로 나뉩니다. 원시 값은 **불변(immutable)** 이고 값 자체가 복사되며, 객체는 **참조(주소)가 복사**됩니다. 그래서 객체를 다른 변수에 할당하고 수정하면 원본도 함께 바뀝니다. 참고로 `typeof null`이 `"object"`인 것은 초기 구현의 버그가 호환성 때문에 남은 것입니다.

> **꼬리 질문**: 얕은 복사와 깊은 복사의 차이는? (`structuredClone`, 스프레드 연산자)

**Q. null과 undefined의 차이는 무엇인가요?**

**A.** `undefined`는 변수를 선언했지만 **값이 할당되지 않았을 때 엔진이 자동으로 부여**하는 값이고, `null`은 개발자가 **의도적으로 "값이 없음"을 표현**할 때 쓰는 값입니다. `null == undefined`는 `true`지만 `null === undefined`는 `false`입니다. 함수가 아무것도 반환하지 않거나, 존재하지 않는 프로퍼티에 접근할 때도 `undefined`가 나옵니다.

**Q. (단골) == 와 === 의 차이는 무엇인가요?**

**A.** `==`는 **동등 연산자**로 비교 전에 **암묵적 타입 변환(type coercion)** 을 수행하고, `===`는 **일치 연산자**로 타입과 값이 모두 같아야 `true`입니다. `==`는 `0 == ''`, `'1' == 1`처럼 예측하기 어려운 결과를 만들 수 있어 실무에서는 `===`를 기본으로 사용합니다. 예외적으로 `x == null`은 `null`과 `undefined`를 함께 걸러낼 때 관용적으로 쓰기도 합니다.

> **꼬리 질문**: `NaN === NaN`의 결과는? 어떻게 NaN을 판별하나요? (`Number.isNaN`, `Object.is`)

**Q. 얕은 복사와 깊은 복사의 차이는 무엇인가요?**

**A.** **얕은 복사(shallow copy)** 는 최상위 프로퍼티만 새로 복사하고 중첩된 객체는 **참조를 공유**합니다. 스프레드 연산자나 `Object.assign`이 여기에 해당합니다. **깊은 복사(deep copy)** 는 중첩된 객체까지 재귀적으로 모두 새로 만들어 원본과 완전히 독립됩니다. 요즘은 `structuredClone`을 쓰고, `JSON.parse(JSON.stringify())`는 함수·`Date`·`undefined` 등을 잃는 한계가 있습니다.

## 스코프와 클로저

**Q. (단골) 실행 컨텍스트(Execution Context)란 무엇인가요?**

**A.** 실행 컨텍스트는 **코드가 실행되기 위해 필요한 환경 정보를 담은 객체**로, 전역 코드나 함수가 실행될 때 생성되어 **콜 스택**에 쌓입니다. 내부에 **렉시컬 환경(Lexical Environment)** — 식별자와 값을 기록하는 환경 레코드와 상위 스코프를 가리키는 외부 환경 참조 — 그리고 **this 바인딩** 정보를 가집니다. 생성 단계에서 선언이 등록되고(호이스팅), 실행 단계에서 값이 할당됩니다. 호이스팅, 스코프 체인, 클로저, this가 모두 이 개념으로 설명됩니다.

> **꼬리 질문**: 콜 스택이 넘치면 어떻게 되나요? (Stack Overflow, 재귀)

**Q. (단골) 스코프(Scope)와 스코프 체인이란 무엇인가요?**

**A.** 스코프는 **식별자가 유효한 범위**로, 전역·함수·블록 스코프가 있습니다. JavaScript는 함수가 **어디서 호출됐는지가 아니라 어디서 정의됐는지**로 상위 스코프가 결정되는 **렉시컬 스코프(정적 스코프)** 를 따릅니다. 식별자를 찾을 때 현재 스코프에서 없으면 외부 환경 참조를 따라 상위 스코프로 올라가며 찾는데, 이 연결을 **스코프 체인**이라고 합니다.

**Q. (단골) 클로저(Closure)란 무엇인가요?**

**A.** 클로저는 **함수와 그 함수가 선언된 렉시컬 환경의 조합**으로, 외부 함수의 실행이 끝난 뒤에도 내부 함수가 **외부 함수의 변수를 계속 참조**할 수 있는 현상입니다. 내부 함수가 외부 렉시컬 환경을 참조하고 있으면 그 환경은 가비지 컬렉션되지 않고 유지됩니다. 주로 **정보 은닉(private 변수)**, 상태 유지, 커링, 디바운스/쓰로틀 같은 고차 함수에 활용됩니다. 다만 불필요하게 큰 객체를 붙잡으면 **메모리 누수**의 원인이 될 수 있습니다.

```js
function counter() {
  let count = 0;
  return () => ++count;
}
const inc = counter();
inc(); // 1
inc(); // 2
```

> **꼬리 질문**: `for (var i...)` 안에서 `setTimeout`으로 i를 찍으면 왜 모두 같은 값이 나오나요? 해결법은? (`let`, IIFE)

**Q. IIFE(즉시 실행 함수)는 무엇이고 왜 사용하나요?**

**A.** IIFE는 **정의와 동시에 즉시 실행되는 함수**로, 함수를 괄호로 감싸 표현식으로 만든 뒤 바로 호출합니다. 모듈 시스템이 없던 시절 **전역 스코프 오염을 막고** 내부 변수를 숨기기 위한 모듈 패턴으로 많이 쓰였습니다. 지금은 ES Modules와 블록 스코프 덕분에 사용 빈도가 줄었지만, 최상위에서 async 함수를 즉시 실행할 때 등에 여전히 쓰입니다.

## this와 함수

**Q. (단골) this는 어떻게 결정되나요?**

**A.** `this`는 함수가 **선언될 때가 아니라 호출되는 방식에 따라 동적으로 결정**됩니다. 일반 함수 호출은 전역 객체(strict mode에서는 `undefined`), **메서드 호출**은 점 앞의 객체, **생성자 호출**(`new`)은 새로 만들어진 인스턴스, `call`/`apply`/`bind`는 명시적으로 지정한 객체가 됩니다. **화살표 함수**는 자신의 `this`가 없고 **상위 스코프의 this를 렉시컬하게** 사용합니다.

> **꼬리 질문**: 콜백으로 메서드를 넘기면 this가 왜 사라지나요? / 이벤트 핸들러에서 this는?

**Q. call, apply, bind의 차이는 무엇인가요?**

**A.** 세 메서드 모두 **this를 명시적으로 지정**합니다. `call`은 인자를 **쉼표로 나열**해 즉시 호출하고, `apply`는 인자를 **배열로** 받아 즉시 호출합니다. `bind`는 호출하지 않고 **this가 고정된 새 함수를 반환**하므로, 콜백으로 넘길 때 this를 유지하는 데 씁니다.

**Q. (단골) 화살표 함수와 일반 함수의 차이는 무엇인가요?**

**A.** 화살표 함수는 **자신만의 this, arguments가 없고** 상위 스코프의 것을 렉시컬하게 참조합니다. **prototype 프로퍼티가 없어 `new`로 생성자 호출을 할 수 없고**, `call`/`apply`/`bind`로 this를 바꿀 수도 없습니다. 그래서 콜백 안에서 바깥 this를 유지할 때 유용하지만, 객체의 메서드나 프로토타입 메서드로 정의하면 this가 객체를 가리키지 않아 문제가 됩니다.

**Q. 일급 객체와 고차 함수란 무엇인가요?**

**A.** JavaScript에서 함수는 **일급 객체(First-class Object)** 라서 변수에 할당하고, 인자로 전달하고, 반환값으로 쓸 수 있습니다. 이를 바탕으로 **함수를 인자로 받거나 함수를 반환하는 함수를 고차 함수(Higher-order Function)** 라 부르며, `map`, `filter`, `reduce`가 대표적입니다. 고차 함수와 클로저 덕분에 커링, 함수 합성 같은 함수형 프로그래밍 기법을 사용할 수 있습니다.

## 프로토타입과 객체지향

**Q. (단골) 프로토타입(Prototype)과 프로토타입 체인이란 무엇인가요?**

**A.** JavaScript는 **프로토타입 기반 언어**로, 모든 객체는 내부 슬롯 `[[Prototype]]`을 통해 자신의 **부모 역할을 하는 프로토타입 객체**를 참조합니다. 객체에서 프로퍼티를 찾을 때 자신에게 없으면 프로토타입을 따라 위로 올라가며 찾는데, 이것이 **프로토타입 체인**이고 끝은 `Object.prototype`, 그 다음은 `null`입니다. 생성자 함수의 `prototype`에 메서드를 정의하면 모든 인스턴스가 **메서드를 공유**해 메모리를 아낄 수 있습니다.

> **꼬리 질문**: `__proto__`와 `prototype`의 차이는? / `Object.create`는 어떻게 동작하나요?

**Q. ES6 class는 기존 프로토타입 방식과 무엇이 다른가요?**

**A.** class는 내부적으로 **프로토타입 기반 상속 위에 만든 문법**이지만 단순한 문법적 설탕 이상입니다. class는 **`new` 없이 호출하면 에러**가 나고, 내부가 **자동으로 strict mode**이며, 선언이 TDZ의 영향을 받고, 메서드는 열거 불가능합니다. 또 `extends`/`super`로 상속을 간결하게 표현하고, `#` 문법의 **private 필드**와 `static` 멤버를 지원합니다.

## 비동기와 이벤트 루프

**Q. (단골) 이벤트 루프(Event Loop)란 무엇인가요?**

**A.** JavaScript 엔진은 **싱글 스레드로 콜 스택 하나**만 가지지만, 브라우저나 Node.js 런타임이 제공하는 Web API(libuv)와 **태스크 큐**, **이벤트 루프** 덕분에 비동기 처리가 가능합니다. 비동기 작업이 끝나면 콜백이 큐에 들어가고, 이벤트 루프는 **콜 스택이 비었을 때 큐에서 콜백을 꺼내 스택에 올립니다**. 이때 Promise 콜백 같은 **마이크로태스크 큐가 매크로태스크 큐보다 우선**하며, 매크로태스크 하나가 끝날 때마다 마이크로태스크 큐를 모두 비웁니다.

```js
console.log(1);
setTimeout(() => console.log(2), 0);
Promise.resolve().then(() => console.log(3));
console.log(4);
// 1 → 4 → 3 → 2
```

> **꼬리 질문**: 마이크로태스크와 매크로태스크의 예시는? / Node.js 이벤트 루프의 phase는? / `process.nextTick`과 Promise의 우선순위는?

**Q. (단골) 마이크로태스크 큐와 매크로태스크(태스크) 큐의 차이는 무엇인가요?**

**A.** **마이크로태스크**에는 `Promise.then/catch/finally`, `queueMicrotask`, `MutationObserver` 콜백이 들어가고, **매크로태스크**에는 `setTimeout`, `setInterval`, I/O, UI 이벤트 콜백이 들어갑니다. 이벤트 루프는 콜 스택이 비면 **마이크로태스크 큐를 끝까지 모두 처리한 뒤** 매크로태스크를 하나 꺼냅니다. 그래서 마이크로태스크를 무한히 추가하면 렌더링이나 타이머가 굶는(starvation) 문제가 생길 수 있습니다.

**Q. (단골) Promise란 무엇이고 콜백과 비교해 어떤 장점이 있나요?**

**A.** Promise는 **비동기 작업의 최종 완료 또는 실패를 나타내는 객체**로, `pending`, `fulfilled`, `rejected` 세 가지 상태를 가지며 한 번 settled되면 바뀌지 않습니다. 콜백 방식은 중첩이 깊어지는 **콜백 지옥**과 에러 처리 분산 문제가 있었는데, Promise는 `then` **체이닝**으로 흐름을 평탄하게 만들고 `catch` 하나로 **에러를 한곳에서 처리**할 수 있습니다. 또 **제어의 역전 문제**(콜백을 몇 번 호출할지 서드파티에 맡기는 문제)도 줄여줍니다.

> **꼬리 질문**: `Promise.all`, `allSettled`, `race`, `any`의 차이는?

**Q. Promise.all, Promise.allSettled, Promise.race, Promise.any의 차이는?**

**A.** `Promise.all`은 **모두 성공하면** 결과 배열을 반환하고 **하나라도 실패하면 즉시 reject**됩니다. `allSettled`는 성공·실패와 무관하게 **모두 끝날 때까지 기다려** 각각의 상태와 결과를 반환합니다. `race`는 **가장 먼저 settled된** 결과를 따르고(타임아웃 구현에 활용), `any`는 **가장 먼저 성공한** 결과를 반환하며 모두 실패하면 `AggregateError`를 던집니다.

**Q. (단골) async/await는 어떻게 동작하나요?**

**A.** async/await는 **Promise 기반의 문법적 설탕**으로, 비동기 코드를 동기 코드처럼 읽히게 만들어 줍니다. `async` 함수는 **항상 Promise를 반환**하고, `await`는 Promise가 settled될 때까지 **해당 함수의 실행만 일시 중단**하고 나머지는 마이크로태스크로 이어서 실행합니다. 스레드를 막는 것이 아니므로 다른 코드는 계속 실행됩니다. 에러 처리는 `try/catch`로 하며, 서로 독립적인 작업을 순차 `await`하면 느려지므로 `Promise.all`로 병렬 처리하는 것이 좋습니다.

```js
// 순차 (느림)
const a = await fetchA();
const b = await fetchB();
// 병렬
const [x, y] = await Promise.all([fetchA(), fetchB()]);
```

**Q. JavaScript가 싱글 스레드인데 어떻게 동시에 여러 작업을 처리하나요?**

**A.** **JavaScript 엔진 자체는 싱글 스레드**지만, 실행 환경(브라우저, Node.js)은 멀티 스레드입니다. 타이머, 네트워크, 파일 I/O 같은 작업은 **브라우저의 Web API나 Node.js의 libuv 스레드 풀/OS 비동기 I/O**에 위임되고, 완료되면 콜백만 큐로 돌아와 이벤트 루프가 처리합니다. 그래서 I/O 바운드 작업에는 강하지만, **CPU를 오래 쓰는 동기 연산은 이벤트 루프를 블로킹**하므로 Worker Threads 등으로 분리해야 합니다.

## 실행 환경과 메모리

**Q. 가비지 컬렉션(Garbage Collection)은 어떻게 동작하나요?**

**A.** JavaScript는 **자동 메모리 관리** 언어로, 엔진이 더 이상 **도달할 수 없는(unreachable) 객체**를 찾아 메모리를 해제합니다. 주로 루트(전역 객체, 콜 스택)에서 참조를 따라가 도달 가능한 객체를 표시하고 나머지를 지우는 **Mark-and-Sweep** 알고리즘을 쓰며, V8은 객체 수명에 따라 Young/Old 영역을 나누는 **세대별(Generational) GC**를 사용합니다. 전역 변수 남용, 해제하지 않은 타이머·이벤트 리스너, 큰 객체를 잡고 있는 클로저가 **메모리 누수**의 흔한 원인입니다.

**Q. 이벤트 버블링, 캡처링, 이벤트 위임이란 무엇인가요?**

**A.** 이벤트는 **캡처링 단계**(window에서 타깃으로 내려감) → **타깃 단계** → **버블링 단계**(타깃에서 상위로 올라감) 순으로 전파됩니다. **이벤트 위임(Event Delegation)** 은 버블링을 이용해 여러 자식 요소에 각각 리스너를 붙이는 대신 **공통 부모에 하나만 등록**하고 `event.target`으로 분기하는 기법입니다. 리스너 수가 줄어 메모리가 절약되고, 동적으로 추가되는 요소도 별도 등록 없이 처리됩니다.

**Q. 디바운스(Debounce)와 쓰로틀(Throttle)의 차이는?**

**A.** 둘 다 **이벤트 호출 빈도를 제한**하는 기법입니다. **디바운스**는 연속 이벤트가 멈춘 뒤 **일정 시간이 지나면 마지막 한 번만** 실행하며, 검색어 자동완성 입력에 적합합니다. **쓰로틀**은 일정 시간 간격마다 **최대 한 번씩** 실행하며, 스크롤이나 리사이즈 이벤트 처리에 적합합니다. 둘 다 클로저로 타이머 상태를 유지해 구현합니다.

## 모듈과 최신 문법

**Q. (단골) CommonJS와 ES Modules의 차이는 무엇인가요?**

**A.** **CommonJS**는 Node.js의 전통적인 모듈 시스템으로 `require`/`module.exports`를 쓰며, **런타임에 동기적으로** 모듈을 로드하고 값의 **복사본**을 가져옵니다. **ES Modules**는 표준 모듈 시스템으로 `import`/`export`를 쓰며, **정적 분석이 가능**해 **트리 셰이킹**이 되고, 비동기 로딩과 top-level await를 지원하며 **live binding**(원본 참조)으로 동작합니다. Node.js에서는 `package.json`의 `"type": "module"`이나 `.mjs` 확장자로 ESM을 사용합니다.

**Q. 이터러블(Iterable)과 제너레이터(Generator)란 무엇인가요?**

**A.** **이터러블**은 `Symbol.iterator` 메서드를 구현해 `for...of`, 스프레드, 구조 분해로 순회할 수 있는 객체이며, 배열·문자열·Map·Set이 해당합니다. **제너레이터**는 `function*`으로 정의하며 `yield`로 **실행을 일시 중지하고 재개**할 수 있는 함수로, 호출하면 이터레이터를 반환합니다. 값을 필요할 때마다 만드는 **지연 평가(lazy evaluation)** 에 유용하고, async/await의 동작 원리를 설명할 때도 등장합니다.

**Q. Map/Set과 일반 Object/Array의 차이는? WeakMap은 언제 쓰나요?**

**A.** `Map`은 **모든 타입을 키로** 쓸 수 있고, 삽입 순서를 보장하며, `size`로 크기를 바로 알 수 있고, 잦은 추가·삭제에 최적화되어 있습니다. `Set`은 **중복 없는 값의 집합**으로 배열 중복 제거에 자주 씁니다. `WeakMap`은 키로 객체만 받고 키를 **약하게 참조**해, 다른 곳에서 키 객체 참조가 사라지면 엔트리가 GC 대상이 됩니다. 그래서 DOM 노드나 객체에 메타데이터를 붙일 때 **메모리 누수 없이** 캐싱하는 데 씁니다.

**Q. 옵셔널 체이닝과 널 병합 연산자는 무엇인가요?**

**A.** **옵셔널 체이닝**(`?.`)은 참조 대상이 `null`이나 `undefined`이면 에러 대신 **`undefined`를 반환하고 평가를 중단**합니다. **널 병합 연산자**(`??`)는 좌항이 `null`이나 `undefined`일 때만 우항을 반환합니다. `||`는 `0`, `''`, `false` 같은 **falsy 값에도 기본값을 적용**해버리지만, `??`는 이런 유효한 값을 그대로 유지한다는 점이 핵심 차이입니다.

**Q. strict mode란 무엇인가요?**

**A.** strict mode는 `'use strict'` 지시어로 활성화하는 **엄격한 실행 모드**로, 잠재적 실수를 에러로 바꿔줍니다. **선언하지 않은 변수 할당 금지**, 일반 함수 호출 시 **this가 `undefined`**, 중복 매개변수 금지, 읽기 전용 프로퍼티 수정 시 에러 등이 대표적입니다. ES Modules와 class 내부는 **자동으로 strict mode**가 적용됩니다.
