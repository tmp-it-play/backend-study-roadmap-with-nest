## 한눈에 보기

- JavaScript 값은 **원시 타입 7종**(불변, 값 자체)과 **객체**(참조)로 나뉜다.
- `typeof null === "object"`는 언어 초기의 버그가 굳어진 것이다. null 체크는 `=== null`로 한다.
- 비교는 기본적으로 `===`를 쓰고, `==`는 `x == null` 패턴 정도에만 쓴다.
- `let`/`const`도 호이스팅되지만 **TDZ** 때문에 선언 전에 접근하면 `ReferenceError`가 난다.
- 스코프는 **코드를 작성한 위치**(lexical)로 결정되고, 안쪽에서 바깥쪽으로 스코프 체인을 따라 변수를 찾는다.

## 1. 값과 타입

> **비유**: 원시 값은 **도장 찍힌 종이**다. 복사하면 똑같은 종이가 한 장 더 생기고, 원본과는 아무 관계가 없다. 객체는 **집 주소가 적힌 쪽지**다. 쪽지를 복사해도 가리키는 집은 하나라서, 한쪽에서 집을 고치면 다른 쪽에서도 바뀐 집을 보게 된다.

### 원시 타입 7종 vs 객체

| 분류 | 타입 | 예시 | 특징 |
| --- | --- | --- | --- |
| 원시 | `string` | `"hello"` | 불변 |
| 원시 | `number` | `42`, `3.14`, `NaN` | IEEE 754 64bit 부동소수점 |
| 원시 | `bigint` | `10n` | 임의 정밀도 정수 |
| 원시 | `boolean` | `true` | |
| 원시 | `undefined` | `undefined` | 값이 할당되지 않음 |
| 원시 | `null` | `null` | 의도적인 "없음" |
| 원시 | `symbol` | `Symbol("id")` | 유일한 식별자 |
| 객체 | `object` | `{}`, `[]`, 함수, `Date` | 참조로 다뤄짐, 가변 |

```js
// 원시 값: 값 자체가 복사된다
let a = 10;
let b = a;
b = 20;
console.log(a); // 10

// 객체: 참조(주소)가 복사된다
const o1 = { n: 1 };
const o2 = o1;
o2.n = 99;
console.log(o1.n); // 99
```

원시 값은 **불변(immutable)** 이다. 문자열 메서드는 원본을 바꾸지 않고 새 문자열을 돌려준다.

```js
const s = "hi";
s[0] = "H";           // 무시됨 (strict mode에서는 TypeError)
console.log(s);        // "hi"
console.log(s.toUpperCase()); // "HI" (새 문자열)
```

> **포인트**: `"hi".toUpperCase()`처럼 원시 값에 메서드를 쓸 수 있는 건, 엔진이 잠깐 `String` 래퍼 객체를 만들었다가 버리기 때문이다(auto-boxing).

### typeof와 그 함정

```js
console.log(typeof "a");          // "string"
console.log(typeof 1);            // "number"
console.log(typeof 1n);           // "bigint"
console.log(typeof true);         // "boolean"
console.log(typeof undefined);    // "undefined"
console.log(typeof Symbol());     // "symbol"
console.log(typeof null);         // "object"   ← 함정!
console.log(typeof {});           // "object"
console.log(typeof []);           // "object"   ← 배열도 object
console.log(typeof function () {}); // "function"
console.log(typeof NaN);          // "number"   ← Not-a-Number인데 number
```

> **주의**: `typeof null`이 `"object"`인 건 초기 구현에서 타입 태그가 0인 값을 객체로 판별했던 버그다. 하위 호환 때문에 고칠 수 없다. null 체크는 `value === null`, 배열 체크는 `Array.isArray(value)`를 쓰자.

```js
function getType(v) {
  if (v === null) return "null";
  if (Array.isArray(v)) return "array";
  return typeof v;
}
console.log(getType(null)); // "null"
console.log(getType([1]));  // "array"

// 가장 정확한 방법
console.log(Object.prototype.toString.call(null));       // "[object Null]"
console.log(Object.prototype.toString.call(new Date())); // "[object Date]"
```

### 동적 타입

> **비유**: 변수는 **이름표가 붙은 빈 상자**다. 상자에 "숫자 전용" 같은 제한이 없어서 아무거나 넣을 수 있다. 타입은 상자가 아니라 **안에 든 물건**에 붙어 있다.

```js
let x = 1;
console.log(typeof x); // "number"
x = "one";
console.log(typeof x); // "string"
x = { one: 1 };
console.log(typeof x); // "object"
```

타입은 **런타임에 값에 따라** 결정된다. 유연하지만, 타입 오류가 실행해 봐야 드러난다는 단점이 있다. TypeScript가 등장한 이유다.

## 2. 형 변환 (Type Coercion)

> **비유**: 암묵적 형 변환은 **눈치 빠른 통역사**다. 내가 말하지 않아도 알아서 바꿔주는데, 가끔 엉뚱하게 바꿔서 사고를 친다. 명시적 형 변환은 **내가 직접 사전을 펴서 번역**하는 것이다.

### 명시적 변환

```js
console.log(Number("42"));     // 42
console.log(Number("42px"));   // NaN
console.log(parseInt("42px")); // 42 (앞에서부터 숫자만 파싱)
console.log(Number(""));       // 0   ← 빈 문자열은 0
console.log(Number(null));     // 0
console.log(Number(undefined));// NaN
console.log(Number([]));       // 0
console.log(Number([5]));      // 5

console.log(String(123));      // "123"
console.log(String(null));     // "null"
console.log(String([1, 2]));   // "1,2"
console.log(String({}));       // "[object Object]"

console.log(Boolean(0));       // false
console.log(Boolean("0"));     // true  ← 비어있지 않은 문자열
```

### 암묵적 변환

```js
// + 는 한쪽이라도 문자열이면 문자열 연결
console.log(1 + "2");      // "12"
console.log("3" - 1);      // 2   (- 는 숫자 연산만 존재)
console.log("3" * "4");    // 12
console.log(true + 1);     // 2
console.log([] + []);      // ""
console.log([] + {});      // "[object Object]"
console.log(null + 1);     // 1
console.log(undefined + 1);// NaN
```

객체가 원시 값으로 바뀔 때는 다음 순서를 따른다.

1. `Symbol.toPrimitive` 메서드가 있으면 호출한다.
2. 없으면 hint가 `"string"`일 때 `toString()` → `valueOf()` 순서로 시도한다.
3. hint가 `"number"`/`"default"`일 때 `valueOf()` → `toString()` 순서로 시도한다.

```js
const price = {
  valueOf() { return 1000; },
  toString() { return "1,000원"; },
};
console.log(price + 500);  // 1500
console.log(`${price}`);   // "1,000원"
```

> **포인트**: 실무에서는 암묵적 변환에 기대지 말고 `Number()`, `String()`, `Boolean()`으로 의도를 드러내자.

## 3. == vs ===

> **비유**: `===`는 **신분증까지 확인하는 출입 검사**(타입과 값 모두 같아야 통과)이고, `==`는 **"대충 비슷하면 들여보내는" 경비원**(타입이 다르면 변환한 뒤 비교)이다.

```js
console.log(1 === "1");        // false
console.log(1 == "1");         // true  ("1" → 1)
console.log(0 == "");          // true
console.log(0 == "0");         // true
console.log("" == "0");        // false  ← 추이성이 깨진다!
console.log(false == "0");     // true
console.log(null == undefined);// true
console.log(null == 0);        // false
console.log(NaN == NaN);       // false
console.log(NaN === NaN);      // false
console.log(Object.is(NaN, NaN)); // true
console.log(Object.is(0, -0));    // false
console.log(0 === -0);            // true
```

| 비교 방식 | 타입 변환 | `NaN` 자기 자신 | `+0` vs `-0` |
| --- | --- | --- | --- |
| `==` | 함 | false | 같음 |
| `===` | 안 함 | false | 같음 |
| `Object.is` | 안 함 | true | 다름 |

> **포인트**: 유일하게 쓸 만한 `==` 패턴은 `value == null`이다. `null`과 `undefined`를 한 번에 거른다.

```js
function greet(name) {
  if (name == null) return "Hello, guest"; // null 또는 undefined
  return `Hello, ${name}`;
}
console.log(greet());      // "Hello, guest"
console.log(greet(null));  // "Hello, guest"
console.log(greet(""));    // "Hello, "  (빈 문자열은 통과)
```

## 4. Truthy / Falsy

> **비유**: 조건문은 **공항 검색대**다. 정해진 "금지 물품 목록"(falsy)에 있으면 걸리고, 그 외는 전부 통과(truthy)한다. 목록이 짧으니 외워두면 된다.

| 값 | Boolean 변환 결과 | 비고 |
| --- | --- | --- |
| `false` | false | |
| `0`, `-0` | false | |
| `0n` | false | BigInt 0 |
| `""` | false | 빈 문자열 |
| `null` | false | |
| `undefined` | false | |
| `NaN` | false | |
| `"0"` | true | 비어있지 않은 문자열 |
| `"false"` | true | |
| `[]` | true | 빈 배열도 객체 |
| `{}` | true | 빈 객체도 객체 |
| `function () {}` | true | |

```js
const items = [];
if (items) console.log("배열은 항상 truthy"); // 출력됨
if (items.length) console.log("비어있지 않음"); // 출력 안 됨

// || 는 falsy면 오른쪽, ?? 는 null/undefined일 때만 오른쪽
const count = 0;
console.log(count || 10); // 10  ← 0이 사라짐!
console.log(count ?? 10); // 0
```

> **주의**: 기본값 처리에 `||`를 쓰면 `0`, `""`, `false` 같은 정상 값이 날아간다. "값이 없을 때만" 기본값을 원하면 `??`(nullish coalescing)를 쓰자.

## 5. var / let / const

> **비유**: `var`는 **회사 전체 공용 화이트보드**(함수 전체에서 보이고 아무나 덮어씀), `let`은 **회의실 화이트보드**(그 방=블록 안에서만 보이고 수정 가능), `const`는 **회의실에 붙인 액자**(그 방 안에서만 보이고 교체 불가)다.

| 항목 | `var` | `let` | `const` |
| --- | --- | --- | --- |
| 스코프 | 함수 | 블록 | 블록 |
| 재선언 | 가능 | 불가 | 불가 |
| 재할당 | 가능 | 가능 | 불가 |
| 호이스팅 | 됨 (`undefined`로 초기화) | 됨 (TDZ) | 됨 (TDZ) |
| 전역 선언 시 `window` 프로퍼티 | 됨 | 안 됨 | 안 됨 |

```js
function demo() {
  if (true) {
    var v = "var";
    let l = "let";
    const c = "const";
  }
  console.log(v); // "var"  ← 블록을 무시하고 함수 스코프
  // console.log(l); // ReferenceError: l is not defined
}
demo();

var dup = 1;
var dup = 2;    // OK (조용히 덮어씀)
let once = 1;
// let once = 2; // SyntaxError: Identifier 'once' has already been declared
```

`const`는 **재할당**을 막을 뿐, 값 자체를 얼리지는 않는다.

```js
const user = { name: "Kim" };
user.name = "Lee";      // OK: 내부 변경은 가능
console.log(user.name); // "Lee"
// user = {};           // TypeError: Assignment to constant variable.
```

> **포인트**: 기본은 `const`, 재할당이 필요할 때만 `let`, `var`는 쓰지 않는다.

## 6. 호이스팅과 TDZ

> **비유**: 호이스팅은 **수업 시작 전 출석부 작성**이다. 선생님(엔진)은 수업(코드 실행) 전에 이 반에 누가 있는지 명단부터 만든다. `var` 학생은 명단에 "자리만 있음(undefined)"으로 적히고, `let`/`const` 학생은 명단에는 있지만 **"아직 입실 전" 상태**라서 이름을 불러도 대답할 수 없다. 이 대기 구간이 TDZ다.

### 동작 흐름

1. 엔진이 코드를 실행하기 전에 스코프 안의 선언을 먼저 훑는다.
2. `var` 변수는 등록과 동시에 `undefined`로 초기화된다.
3. `let`/`const` 변수는 등록만 되고 **초기화되지 않는다** (TDZ 시작).
4. 함수 선언문은 **함수 객체 전체**가 등록된다.
5. 실제 선언문 줄에 도달하면 `let`/`const`가 초기화된다 (TDZ 종료).

```js
console.log(a); // undefined
var a = 1;

// console.log(b); // ReferenceError: Cannot access 'b' before initialization
let b = 2;

sayHi(); // "hi"  ← 함수 선언문은 통째로 호이스팅
function sayHi() {
  console.log("hi");
}

// sayBye(); // TypeError: sayBye is not a function
var sayBye = function () {
  console.log("bye");
};
```

TDZ는 "선언이 아예 없는 것"과 다르다. 바깥에 같은 이름이 있어도 가려진다.

```js
const x = "outer";
{
  // console.log(x); // ReferenceError! (바깥 x가 아니라 TDZ인 안쪽 x를 봄)
  const x = "inner";
  console.log(x); // "inner"
}
```

`typeof`조차 TDZ에서는 안전하지 않다.

```js
console.log(typeof notDeclared); // "undefined" (선언이 아예 없으면 OK)
// console.log(typeof inTdz);    // ReferenceError
let inTdz = 1;
```

> **주의**: "let/const는 호이스팅되지 않는다"는 흔한 오해다. 호이스팅은 되지만 초기화가 안 됐을 뿐이다. 위 예제처럼 바깥 변수가 가려지는 현상이 그 증거다.

## 7. 스코프

> **비유**: 스코프는 **건물의 층과 방**이다. 방(블록) 안에서는 방 안 물건, 층(함수) 물건, 로비(전역) 물건을 모두 볼 수 있다. 하지만 로비에서는 방 안을 볼 수 없다. 바깥에서 안은 못 보고, 안에서 바깥은 볼 수 있다.

### 전역 / 함수 / 블록 스코프

```js
const globalVar = "전역";

function outer() {
  const fnVar = "함수";
  if (true) {
    const blockVar = "블록";
    console.log(globalVar, fnVar, blockVar); // 전역 함수 블록
  }
  // console.log(blockVar); // ReferenceError
}
outer();
// console.log(fnVar); // ReferenceError
```

### 스코프 체인

변수를 찾을 때 엔진은 다음 순서로 움직인다.

1. 현재 스코프에서 찾는다.
2. 없으면 바로 바깥(상위) 스코프로 올라간다.
3. 전역 스코프까지 반복한다.
4. 전역에도 없으면 `ReferenceError`.

```js
const level = "global";

function a() {
  const level = "a";
  function b() {
    function c() {
      console.log(level); // c → b → a 순서로 찾다가 a에서 발견
    }
    c();
  }
  b();
}
a(); // "a"
```

> **포인트**: 안쪽 스코프에 같은 이름을 선언하면 바깥 변수를 가린다(shadowing). 의도치 않은 shadowing은 버그의 원인이 되니 ESLint `no-shadow`로 잡을 수 있다.

### 렉시컬 스코프

> **비유**: 렉시컬 스코프는 **출생지 기준 국적**이다. 함수가 어디서 **호출**되든(어디로 여행하든) 상관없이, 어디서 **정의**됐는지(어디서 태어났는지)로 바깥 스코프가 결정된다.

```js
const name = "global";

function printName() {
  console.log(name); // 정의된 위치 기준으로 바깥 = 전역
}

function caller() {
  const name = "caller";
  printName(); // 호출 위치와 무관
}

caller(); // "global"
```

만약 호출 위치 기준(dynamic scope)이었다면 `"caller"`가 찍혔을 것이다. JavaScript는 렉시컬 스코프이고, 이 성질이 바로 **클로저**의 기반이 된다. (단, `this`는 예외적으로 호출 방식에 따라 정해진다. 다음 글에서 다룬다.)

## 8. 실행 컨텍스트 개요

> **비유**: 실행 컨텍스트는 **요리 한 건을 위한 작업대**다. 요리(함수 호출)를 시작하면 작업대를 펴고, 먼저 **재료 목록을 정리**(생성 단계)한 뒤 **실제로 조리**(실행 단계)한다. 요리 중에 다른 요리를 부르면 그 위에 새 작업대를 쌓는다(콜 스택).

### 구성 요소

| 구성 요소 | 담는 것 |
| --- | --- |
| LexicalEnvironment | `let`/`const`/함수 선언 등 식별자 바인딩 + 바깥 환경 참조(outer) |
| VariableEnvironment | `var` 선언 바인딩 |
| this 바인딩 | 현재 컨텍스트의 `this` 값 (화살표 함수는 갖지 않음) |

### 두 단계

1. **생성 단계 (Creation Phase)**
   - 환경 레코드를 만들고 선언을 등록한다 (호이스팅의 실체).
   - `var` → `undefined`, `let`/`const` → 미초기화(TDZ), 함수 선언 → 함수 객체.
   - outer 참조를 **정의된 위치의 환경**으로 연결한다 (렉시컬 스코프의 실체).
   - `this`를 결정한다.
2. **실행 단계 (Execution Phase)**
   - 코드를 위에서 아래로 실행하며 값을 할당한다.

```js
function multiply(x) {
  // [생성 단계] x = 3, result = undefined, helper = function, k = TDZ
  console.log(result); // undefined
  console.log(helper()); // "helper"
  var result = x * 2;
  let k = 10;
  function helper() { return "helper"; }
  return result + k;
}
console.log(multiply(3)); // 16
```

### 콜 스택

```js
function first() {
  console.log("first 시작");
  second();
  console.log("first 끝");
}
function second() {
  console.log("second");
}
first();
// first 시작
// second
// first 끝
```

```text
[ 전역 컨텍스트 ]
[ 전역 ] → [ first ]
[ 전역 ] → [ first ] → [ second ]
[ 전역 ] → [ first ]          (second 종료 후 pop)
[ 전역 ]                      (first 종료 후 pop)
```

> **주의**: 재귀 호출에 종료 조건이 없으면 컨텍스트가 무한히 쌓여 `RangeError: Maximum call stack size exceeded`가 난다.

## 9. Strict Mode

> **비유**: strict mode는 **엄격한 코드 리뷰어**다. 예전에는 조용히 넘어가던 실수를 "이건 에러야"라고 바로 지적해 준다.

파일이나 함수 맨 위에 `"use strict";`를 쓰면 켜진다. **ES Module과 `class` 본문은 자동으로 strict mode**다.

```js
"use strict";

// 1) 선언 안 한 변수에 할당 → ReferenceError
// undeclared = 1; // ReferenceError: undeclared is not defined

// 2) 일반 함수 호출 시 this가 undefined
function whoAmI() {
  return this;
}
console.log(whoAmI()); // undefined (sloppy mode에서는 globalThis)

// 3) 읽기 전용 프로퍼티 변경 → TypeError
const frozen = Object.freeze({ a: 1 });
// frozen.a = 2; // TypeError: Cannot assign to read only property 'a'

// 4) 중복 매개변수 이름 → SyntaxError
// function f(a, a) {} // SyntaxError
```

| 상황 | sloppy mode | strict mode |
| --- | --- | --- |
| 미선언 변수 할당 | 전역 변수 생성 | `ReferenceError` |
| 일반 함수의 `this` | `globalThis` | `undefined` |
| frozen 객체 수정 | 조용히 무시 | `TypeError` |
| `with` 문 | 허용 | `SyntaxError` |
| 중복 매개변수 | 허용 | `SyntaxError` |

> **포인트**: 요즘 번들러/모듈 환경에서 작성하는 코드는 대부분 이미 strict mode다. 그래서 "함수 안의 `this`가 `undefined`"인 상황을 자주 만나게 된다.

## 셀프 체크

**Q1. `typeof null`의 결과와, null 여부를 정확히 검사하는 방법은?**

**A.** `"object"`가 나온다. 초기 구현 버그가 하위 호환 때문에 남은 것이다. null은 `value === null`로 검사하고, null과 undefined를 함께 거르려면 `value == null`을 쓴다.

**Q2. 다음 코드의 출력은? `const n = 0; console.log(n || 5, n ?? 5);`**

**A.** `5 0`이 출력된다. `||`는 falsy인 0을 버리고 오른쪽을 택하지만, `??`는 null/undefined일 때만 오른쪽을 택하므로 0을 유지한다.

**Q3. `let`은 호이스팅되지 않는다는 말은 맞는가?**

**A.** 틀리다. `let`/`const`도 생성 단계에서 등록(호이스팅)되지만 초기화되지 않아 TDZ에 놓인다. 그래서 같은 이름의 바깥 변수가 있어도 선언 전 접근 시 바깥 값이 아니라 `ReferenceError`가 난다.

**Q4. 함수 안에서 바깥 변수를 참조할 때, 어떤 바깥 스코프를 보는지는 무엇으로 결정되는가?**

**A.** 함수가 **정의된 위치**(렉시컬 스코프)로 결정된다. 호출 위치와는 무관하다. 실행 컨텍스트 생성 시 outer 참조가 정의 위치의 환경으로 연결되기 때문이다.

**Q5. strict mode에서 일반 함수로 호출한 `function f() { return this; }`의 결과는?**

**A.** `undefined`다. sloppy mode였다면 `globalThis`(브라우저에서는 `window`)가 된다.

## 핵심 정리

- 값은 원시 타입 7종(`string`, `number`, `bigint`, `boolean`, `undefined`, `null`, `symbol`)과 객체로 나뉘며, 원시는 값 복사, 객체는 참조 복사다.
- `typeof null`은 `"object"`, 배열은 `Array.isArray`로 판별한다.
- 형 변환은 명시적으로 하고, 비교는 `===`, 기본값은 `??`를 우선한다.
- falsy는 `false`, `0`, `-0`, `0n`, `""`, `null`, `undefined`, `NaN` 8개뿐이고 나머지는 전부 truthy다.
- `const` 우선, `let`은 필요할 때, `var`는 쓰지 않는다. `const`는 재할당만 막는다.
- 호이스팅은 실행 컨텍스트 생성 단계에서 선언을 등록하는 것이고, `let`/`const`는 TDZ 때문에 선언 전 접근이 에러다.
- 스코프는 렉시컬하게 결정되고, 스코프 체인을 따라 안쪽에서 바깥쪽으로 탐색한다.
- 모듈과 클래스는 자동 strict mode이며, 일반 함수 호출의 `this`는 `undefined`다.
