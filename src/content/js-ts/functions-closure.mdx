## 한눈에 보기

- JavaScript 함수는 **일급 객체**라서 변수에 담고, 인자로 넘기고, 반환할 수 있다. 고차 함수와 콜백이 여기서 나온다.
- **클로저** = 함수 + 그 함수가 정의될 때의 렉시컬 환경. 외부 함수가 끝나도 변수가 살아남는다.
- `this`는 정의 위치가 아니라 **호출 방식**으로 결정된다: 기본 → 암시적 → 명시적 → `new` 순으로 우선순위가 올라간다.
- 화살표 함수는 자신의 `this`가 없고 **바깥 스코프의 `this`를 그대로 쓴다**(lexical this).
- 메서드를 콜백으로 넘기면 `this`를 잃는다. `bind`나 화살표 함수로 고정하자.

## 1. 함수를 만드는 세 가지 방법

> **비유**: 함수 선언문은 **건물 안내판에 미리 적혀 있는 매장**(입장 전부터 위치를 알 수 있음), 함수 표현식은 **오픈 당일에 간판을 다는 매장**(그 시점 전에는 찾을 수 없음), 화살표 함수는 **본사 규정을 그대로 따르는 프랜차이즈 키오스크**(자기만의 `this`/`arguments` 없이 바깥 것을 씀)다.

```js
// 1) 함수 선언문
function add(a, b) {
  return a + b;
}

// 2) 함수 표현식
const sub = function (a, b) {
  return a - b;
};

// 3) 화살표 함수
const mul = (a, b) => a * b;

console.log(add(2, 3), sub(5, 1), mul(3, 4)); // 5 4 12
```

| 항목 | 선언문 | 표현식 | 화살표 함수 |
| --- | --- | --- | --- |
| 호이스팅 | 함수 전체 | 변수만 (TDZ 또는 `undefined`) | 변수만 |
| 자신의 `this` | 있음 (호출 방식으로 결정) | 있음 | 없음 (lexical) |
| `arguments` 객체 | 있음 | 있음 | 없음 |
| `new`로 호출 | 가능 | 가능 | 불가 (`TypeError`) |
| `prototype` 프로퍼티 | 있음 | 있음 | 없음 |

```js
const arrow = () => arguments;
// arrow(); // 모듈 환경: ReferenceError: arguments is not defined

function regular() {
  return arguments.length;
}
console.log(regular(1, 2, 3)); // 3

const Arrow = () => {};
// new Arrow(); // TypeError: Arrow is not a constructor
```

> **포인트**: 화살표 함수에서 객체 리터럴을 바로 반환하려면 괄호로 감싸야 한다. `() => ({ a: 1 })`. 괄호가 없으면 중괄호가 함수 본문으로 해석된다.

## 2. 일급 함수와 고차 함수

> **비유**: 일급 함수는 **함수가 일반 시민권을 가진 것**이다. 숫자나 문자열처럼 어디든 들고 다닐 수 있다. 고차 함수는 **작업 지시서를 받아서 일하는 관리자**다. "무엇을 할지"는 지시서(함수)로 받고, "언제/어떻게 반복할지"는 관리자가 책임진다.

일급 함수의 조건:

1. 변수에 할당할 수 있다.
2. 다른 함수의 인자로 전달할 수 있다.
3. 다른 함수의 반환값이 될 수 있다.
4. 자료구조(배열, 객체)에 저장할 수 있다.

```js
const ops = { add: (a, b) => a + b, mul: (a, b) => a * b };
console.log(ops.add(1, 2)); // 3

// 함수를 인자로 받는 고차 함수
function repeat(n, action) {
  for (let i = 0; i < n; i++) action(i);
}
repeat(3, (i) => console.log(`step ${i}`));
// step 0
// step 1
// step 2

// 함수를 반환하는 고차 함수
function multiplier(factor) {
  return (x) => x * factor;
}
const double = multiplier(2);
console.log(double(21)); // 42

// 내장 고차 함수
const nums = [1, 2, 3, 4, 5];
const result = nums
  .filter((n) => n % 2 === 1)
  .map((n) => n * 10)
  .reduce((acc, n) => acc + n, 0);
console.log(result); // 90
```

### 콜백

콜백은 **나중에 불러달라고 넘기는 함수**다. 동기 콜백(`map`, `forEach`)과 비동기 콜백(`setTimeout`, 이벤트 핸들러)이 있다.

```js
console.log("A");
[1, 2].forEach((n) => console.log("sync", n)); // 동기: 즉시 실행
setTimeout(() => console.log("async"), 0);     // 비동기: 콜 스택이 빈 뒤 실행
console.log("B");
// A
// sync 1
// sync 2
// B
// async
```

> **주의**: 비동기 콜백을 계속 중첩하면 콜백 지옥이 된다. 지금은 Promise와 async/await로 평평하게 쓰는 게 표준이다.

## 3. 기본 매개변수와 rest 파라미터

```js
function greet(name = "guest", greeting = `Hi, ${name}`) {
  return greeting;
}
console.log(greet());          // "Hi, guest"
console.log(greet("Kim"));     // "Hi, Kim"
console.log(greet(undefined)); // "Hi, guest"  ← undefined면 기본값
console.log(greet(null));      // "Hi, null"   ← null은 기본값 적용 안 됨

function sum(first, ...rest) {
  console.log(first, rest);
  return rest.reduce((a, b) => a + b, first);
}
console.log(sum(1, 2, 3, 4));
// 1 [ 2, 3, 4 ]
// 10
```

| 비교 | `arguments` | rest 파라미터 |
| --- | --- | --- |
| 타입 | 유사 배열 객체 | 진짜 배열 |
| 배열 메서드 | 직접 못 씀 | `map`, `reduce` 바로 사용 |
| 화살표 함수 | 없음 | 사용 가능 |
| 범위 | 모든 인자 | 지정한 위치 이후 인자 |

> **포인트**: 기본값은 **호출할 때마다** 평가된다. `function f(arr = [])`는 매 호출마다 새 배열을 만든다(Python의 mutable default 함정이 없다).

## 4. 클로저

> **비유**: 클로저는 **배낭을 메고 집을 나서는 아이**다. 집(외부 함수)이 문을 닫아도(실행이 끝나도) 아이(내부 함수)는 집에서 챙긴 물건(변수)을 배낭에 넣어 들고 다닌다. 그리고 그 배낭은 아이만 열 수 있다.

### 동작 흐름

1. 외부 함수가 호출되면 렉시컬 환경(변수 저장소)이 생긴다.
2. 내부 함수가 정의될 때 그 환경을 **참조**로 기억한다.
3. 외부 함수가 반환되어도, 내부 함수가 그 환경을 참조하고 있으므로 GC가 수거하지 않는다.
4. 내부 함수를 호출할 때마다 같은 환경의 변수를 읽고 쓴다.

### 카운터

```js
function createCounter() {
  let count = 0; // 외부에서 직접 접근 불가
  return {
    inc: () => ++count,
    dec: () => --count,
    get: () => count,
  };
}

const c1 = createCounter();
const c2 = createCounter();
c1.inc();
c1.inc();
c2.inc();
console.log(c1.get(), c2.get()); // 2 1  ← 호출마다 독립된 환경
console.log(c1.count);           // undefined
```

### private 상태 캡슐화

```js
function createBankAccount(initial) {
  let balance = initial;
  const history = [];

  function record(type, amount) {
    history.push({ type, amount, balance });
  }

  return {
    deposit(amount) {
      if (amount <= 0) throw new Error("양수만 가능");
      balance += amount;
      record("deposit", amount);
    },
    withdraw(amount) {
      if (amount > balance) throw new Error("잔액 부족");
      balance -= amount;
      record("withdraw", amount);
    },
    getBalance: () => balance,
    getHistory: () => [...history], // 복사본을 넘겨 외부 변경 차단
  };
}

const acc = createBankAccount(1000);
acc.deposit(500);
acc.withdraw(200);
console.log(acc.getBalance()); // 1300
console.log(acc.getHistory().length); // 2
```

### 반복문 var 함정

```js
var fns = [];
for (var i = 0; i < 3; i++) {
  fns.push(() => i);
}
console.log(fns.map((f) => f())); // [ 3, 3, 3 ]
```

`var i`는 함수 스코프라서 변수가 **하나뿐**이다. 세 클로저가 모두 같은 `i`를 참조하고, 호출 시점에 `i`는 이미 3이다.

```js
// 해결 1: let → 반복마다 새 바인딩이 생성된다
const fixed = [];
for (let j = 0; j < 3; j++) {
  fixed.push(() => j);
}
console.log(fixed.map((f) => f())); // [ 0, 1, 2 ]

// 해결 2: IIFE로 값 복사 (ES5 시절 방식)
var old = [];
for (var k = 0; k < 3; k++) {
  (function (captured) {
    old.push(() => captured);
  })(k);
}
console.log(old.map((f) => f())); // [ 0, 1, 2 ]
```

> **주의**: 클로저는 값이 아니라 **변수(바인딩) 자체**를 캡처한다. 캡처 후 변수가 바뀌면 클로저도 바뀐 값을 본다.

> **주의**: 클로저가 큰 객체(DOM 노드, 대용량 배열)를 붙잡고 있으면 메모리 누수가 된다. 이벤트 리스너는 쓰고 나면 `removeEventListener`로 해제하자.

## 5. 클로저 활용 패턴

### 커링 (Currying)

> **비유**: 커링은 **주문서를 한 칸씩 채우는 것**이다. 사이즈를 먼저 정하고, 다음에 맛을 정하고, 마지막에 토핑을 정하면 주문이 완성된다. 중간 단계의 주문서(부분 적용된 함수)를 재사용할 수 있다.

```js
function curry(fn) {
  return function curried(...args) {
    if (args.length >= fn.length) {
      return fn.apply(this, args);
    }
    return (...next) => curried.apply(this, [...args, ...next]);
  };
}

const volume = (l, w, h) => l * w * h;
const cVolume = curry(volume);
console.log(cVolume(2)(3)(4)); // 24
console.log(cVolume(2, 3)(4)); // 24

const log = curry((level, tag, msg) => `[${level}][${tag}] ${msg}`);
const errorApi = log("ERROR")("api");
console.log(errorApi("timeout")); // "[ERROR][api] timeout"
```

### 메모이제이션 (Memoization)

> **비유**: 메모이제이션은 **계산기 옆의 메모장**이다. 한 번 푼 문제의 답은 적어두고, 같은 문제가 오면 다시 계산하지 않고 메모를 본다.

```js
function memoize(fn) {
  const cache = new Map(); // 클로저로 캐시 보관
  return function (...args) {
    const key = JSON.stringify(args);
    if (cache.has(key)) return cache.get(key);
    const value = fn.apply(this, args);
    cache.set(key, value);
    return value;
  };
}

let calls = 0;
const slowSquare = (n) => {
  calls++;
  return n * n;
};
const fastSquare = memoize(slowSquare);
fastSquare(9);
fastSquare(9);
fastSquare(9);
console.log(calls); // 1

const fib = memoize((n) => (n < 2 ? n : fib(n - 1) + fib(n - 2)));
console.log(fib(50)); // 12586269025
```

> **주의**: `JSON.stringify` 키는 객체 인자, 함수 인자, 순서가 다른 프로퍼티를 제대로 구분하지 못한다. 순수 함수 + 원시 인자에만 쓰고, 캐시 크기 제한(LRU)도 고려하자.

### Debounce

> **비유**: debounce는 **엘리베이터 문**이다. 사람이 계속 타면 문 닫힘 타이머가 계속 리셋되고, 마지막 사람이 탄 뒤 일정 시간이 지나야 출발한다.

```js
function debounce(fn, wait) {
  let timer = null;
  return function (...args) {
    clearTimeout(timer);
    timer = setTimeout(() => fn.apply(this, args), wait);
  };
}

const search = debounce((q) => console.log("search:", q), 300);
search("j");
search("ja");
search("jav");
search("java");
// (300ms 후) search: java   ← 마지막 호출만 실행
```

### Throttle

> **비유**: throttle은 **지하철 배차 간격**이다. 승객이 아무리 몰려도 열차는 정해진 간격마다 한 대씩만 출발한다.

```js
function throttle(fn, interval) {
  let last = 0;
  return function (...args) {
    const now = Date.now();
    if (now - last >= interval) {
      last = now;
      fn.apply(this, args);
    }
  };
}

const onScroll = throttle(() => console.log("scroll", Date.now()), 200);
// window.addEventListener("scroll", onScroll);
// 연속 스크롤 중에도 200ms마다 최대 1번만 실행
```

| 비교 | debounce | throttle |
| --- | --- | --- |
| 실행 시점 | 입력이 멈춘 뒤 한 번 | 일정 간격마다 한 번 |
| 대표 용도 | 검색 자동완성, 폼 검증, resize 종료 | 스크롤 위치, 무한 스크롤, mousemove |
| 연속 입력 중 | 실행 안 됨 | 주기적으로 실행 |

> **포인트**: 위 구현들은 모두 `timer`, `last`, `cache` 같은 상태를 **클로저로 숨긴다**. 클로저 = 함수에 딸린 private 상태라는 감각을 잡자.

## 6. this 바인딩

> **비유**: `this`는 **"저 사람"이라는 대명사**다. 같은 문장이라도 누가 말하느냐(어떻게 호출하느냐)에 따라 가리키는 대상이 달라진다. 반면 화살표 함수는 대명사를 쓰지 않고 **"아까 그 사람"이라고 바깥 문맥에 기대는 화자**다.

### 4가지 규칙

| 규칙 | 호출 형태 | `this` | 우선순위 |
| --- | --- | --- | --- |
| 기본 바인딩 | `fn()` | strict: `undefined`, sloppy: `globalThis` | 4 (가장 낮음) |
| 암시적 바인딩 | `obj.fn()` | `obj` (점 앞의 객체) | 3 |
| 명시적 바인딩 | `fn.call(obj)`, `fn.bind(obj)()` | `obj` | 2 |
| `new` 바인딩 | `new Fn()` | 새로 만든 객체 | 1 (가장 높음) |

```js
"use strict";

function show() {
  return this;
}

// 1) 기본 바인딩
console.log(show()); // undefined

// 2) 암시적 바인딩
const obj = { name: "obj", show };
console.log(obj.show().name); // "obj"

// 3) 명시적 바인딩
const other = { name: "other" };
console.log(show.call(other).name); // "other"

// 4) new 바인딩
function Person(name) {
  this.name = name;
}
const p = new Person("Kim");
console.log(p.name); // "Kim"
```

`this`를 판별하는 순서:

1. `new`로 호출했나? → 새 객체
2. `call`/`apply`/`bind`로 호출했나? → 지정한 객체
3. `obj.method()` 형태인가? → `obj`
4. 그 외 → `undefined`(strict) 또는 `globalThis`
5. 단, **화살표 함수라면 위 규칙을 전부 무시**하고 정의된 곳의 `this`를 쓴다.

```js
// new가 bind보다 우선
function Box(v) { this.v = v; }
const Bound = Box.bind({ v: "bound" });
const b = new Bound("new");
console.log(b.v); // "new"
```

### 화살표 함수의 lexical this

```js
const timer = {
  seconds: 0,
  startRegular() {
    setTimeout(function () {
      // 일반 함수: 기본 바인딩 → this는 timer가 아님
      console.log("regular:", this === timer); // false
    }, 0);
  },
  startArrow() {
    setTimeout(() => {
      // 화살표: startArrow의 this(= timer)를 그대로 사용
      this.seconds++;
      console.log("arrow:", this.seconds); // 1
    }, 0);
  },
};
timer.startRegular();
timer.startArrow();
```

> **주의**: 객체 메서드를 화살표 함수로 정의하면 안 된다. 객체 리터럴은 스코프를 만들지 않으므로 `this`가 바깥(모듈이면 `undefined`)을 가리킨다.

```js
const bad = {
  name: "bad",
  hello: () => this?.name, // 바깥 this
};
console.log(bad.hello()); // undefined
```

### call / apply / bind

```js
function intro(greeting, punct) {
  return `${greeting}, I'm ${this.name}${punct}`;
}
const kim = { name: "Kim" };

console.log(intro.call(kim, "Hi", "!"));    // "Hi, I'm Kim!"     인자를 나열
console.log(intro.apply(kim, ["Hey", "?"])); // "Hey, I'm Kim?"   인자를 배열로
const bound = intro.bind(kim, "Hello");      // 새 함수 반환 (부분 적용 가능)
console.log(bound("~"));                     // "Hello, I'm Kim~"

// bind는 한 번만 유효하다
const rebound = bound.bind({ name: "Lee" });
console.log(rebound("."));                   // "Hello, I'm Kim."
```

| 메서드 | 즉시 실행 | 인자 전달 | 반환값 |
| --- | --- | --- | --- |
| `call` | O | 쉼표로 나열 | 함수 실행 결과 |
| `apply` | O | 배열 하나 | 함수 실행 결과 |
| `bind` | X | 쉼표로 나열 (부분 적용) | `this`가 고정된 새 함수 |

### this를 잃어버리는 문제

> **비유**: 메서드를 변수에 꺼내 담는 건 **명함에서 이름만 오려내는 것**이다. 오려낸 종이에는 "누구의" 명함이었는지 정보가 없다.

```js
"use strict";

class Counter {
  count = 0;
  inc() {
    this.count++;
    return this.count;
  }
}

const counter = new Counter();
const inc = counter.inc; // 메서드를 떼어냄
// inc(); // TypeError: Cannot read properties of undefined (reading 'count')

// 콜백으로 넘길 때도 똑같다
// setTimeout(counter.inc, 0);           // this 잃어버림
// button.addEventListener("click", counter.inc); // this === button
```

해결 방법 세 가지:

```js
class SafeCounter {
  count = 0;

  // 1) 클래스 필드 + 화살표 함수: 인스턴스마다 this가 고정된 함수
  incArrow = () => ++this.count;

  // 2) 생성자에서 bind
  constructor() {
    this.incBound = this.incBound.bind(this);
  }
  incBound() {
    return ++this.count;
  }
}

const sc = new SafeCounter();
const f1 = sc.incArrow;
const f2 = sc.incBound;
console.log(f1(), f2()); // 1 2

// 3) 호출하는 쪽에서 화살표 함수로 감싸기
setTimeout(() => console.log(sc.incBound()), 0); // 3
```

이벤트 핸들러에서의 `this`:

```js
// 브라우저
// const btn = document.querySelector("button");
// btn.addEventListener("click", function () {
//   console.log(this === btn); // true  (currentTarget)
// });
// btn.addEventListener("click", () => {
//   console.log(this);         // 바깥 this (모듈이면 undefined)
// });
```

> **포인트**: 클래스 필드 화살표 함수는 인스턴스마다 함수가 새로 생기고 `prototype`에 없다. 인스턴스가 아주 많다면 메모리 비용을 고려하자. 보통의 UI 컴포넌트에서는 무시해도 되는 수준이다.

## 7. IIFE (즉시 실행 함수 표현식)

> **비유**: IIFE는 **일회용 칸막이 방**이다. 들어가서 작업하고 나오면 방이 사라지고, 안에서 쓴 물건(변수)은 바깥을 어지럽히지 않는다.

```js
const config = (function () {
  const secret = "s3cr3t"; // 외부에서 접근 불가
  const env = "prod";
  return {
    env,
    isProd: () => env === "prod",
  };
})();

console.log(config.env);      // "prod"
console.log(config.isProd()); // true
console.log(typeof secret);   // "undefined"

// 화살표 함수 IIFE, async IIFE
(() => console.log("arrow IIFE"))();
(async () => {
  const v = await Promise.resolve(42);
  console.log("async IIFE", v); // async IIFE 42
})();
```

과거에는 전역 오염을 막는 **모듈 패턴**의 핵심이었다. 지금은 ES Module과 블록 스코프가 그 역할을 대신하고, IIFE는 주로 top-level await가 없는 환경에서 `async` 코드를 실행할 때 쓴다.

## 셀프 체크

**Q1. 함수 선언문과 함수 표현식을 선언 전에 호출하면 각각 어떻게 되는가?**

**A.** 선언문은 함수 전체가 호이스팅되어 정상 실행된다. 표현식은 변수만 호이스팅되므로 `var`라면 `TypeError: ... is not a function`, `let`/`const`라면 TDZ 때문에 `ReferenceError`가 난다.

**Q2. `for (var i = 0; i < 3; i++) setTimeout(() => console.log(i))`의 출력과 그 이유는?**

**A.** `3 3 3`이다. `var`는 함수 스코프라 `i` 바인딩이 하나뿐이고, 세 콜백이 모두 같은 `i`를 캡처한다. 콜백이 실행될 때는 루프가 끝나 `i`가 3이다. `let`으로 바꾸면 반복마다 새 바인딩이 생겨 `0 1 2`가 된다.

**Q3. debounce와 throttle의 차이를 한 문장씩 설명하라.**

**A.** debounce는 연속 호출이 **멈춘 뒤** 마지막 한 번만 실행하고, throttle은 연속 호출 중에도 **일정 간격마다** 최대 한 번씩 실행한다.

**Q4. `const f = obj.method; f();`에서 `this`가 `obj`가 아닌 이유와 해결법은?**

**A.** `this`는 호출 방식으로 결정되는데, `f()`는 점 앞에 객체가 없는 기본 바인딩이라 strict mode에서 `undefined`가 된다. `obj.method.bind(obj)`, 클래스 필드 화살표 함수, 또는 `() => obj.method()`로 감싸서 해결한다.

**Q5. `bind`로 묶은 함수를 `new`로 호출하면 `this`는 무엇인가?**

**A.** `new` 바인딩이 명시적 바인딩보다 우선하므로, `bind`에 넘긴 객체가 아니라 새로 생성된 인스턴스가 `this`가 된다.

## 핵심 정리

- 함수 선언문은 통째로 호이스팅되고, 표현식/화살표 함수는 변수 규칙을 따른다.
- 화살표 함수에는 `this`, `arguments`, `prototype`이 없고 `new`로 호출할 수 없다.
- 함수는 일급 객체이며, 함수를 받거나 반환하는 고차 함수로 동작을 조립한다.
- 기본 매개변수는 `undefined`일 때만 적용되고, rest 파라미터는 진짜 배열이다.
- 클로저는 정의 시점의 렉시컬 환경(변수 바인딩)을 기억하며, private 상태와 캐시를 숨기는 도구다.
- 커링, 메모이제이션, debounce, throttle은 모두 클로저로 상태를 감춘 고차 함수다.
- `this` 우선순위: `new` → 명시적(`call`/`apply`/`bind`) → 암시적(`obj.fn()`) → 기본.
- 메서드를 떼어 콜백으로 넘기면 `this`를 잃는다. `bind`, 클래스 필드 화살표 함수, 래퍼 화살표 함수로 고정한다.
- IIFE는 일회용 스코프를 만드는 패턴이며, 지금은 주로 async IIFE로 쓰인다.
