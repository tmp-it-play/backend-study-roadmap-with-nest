## 한눈에 보기

- 없을 수도 있는 값은 `?.`로 안전하게 접근하고, 기본값은 `||`보다 `??`로 준다 (`0`, `""`, `false` 보존).
- 배열은 `at(-1)`, `findLast`, `flatMap`, 그리고 원본을 안 바꾸는 `toSorted` / `toReversed` / `toSpliced` / `with`를 쓰자.
- 깊은 복사는 `structuredClone`, 객체 가공은 `Object.entries` + `Object.fromEntries`, 그룹핑은 `Object.groupBy`.
- 클래스의 진짜 private은 `#필드`, 큰 정수는 `BigInt`, 집합 연산은 `Set.prototype.union` 등.
- 모듈은 표준인 ESM(`import` / `export`)이 기본이고, CJS와는 로딩 방식·바인딩이 다르다.

## Optional Chaining `?.` (ES2020)

> **비유**: 아파트 동 → 호수 → 우편함 순서로 택배를 찾아가는데, 중간에 "그런 동이 없네?" 하면 소란 피우지 않고(에러 없이) 조용히 "없음"(`undefined`)을 들고 돌아오는 배달원.

중간 값이 `null` 또는 `undefined`이면 에러를 던지지 않고 즉시 `undefined`를 반환한다(short-circuit).

```js
const user = { profile: null };

// 예전 방식
const city1 = user && user.profile && user.profile.address && user.profile.address.city;

// Optional Chaining
const city2 = user?.profile?.address?.city; // undefined (에러 없음)

// 메서드 호출
user.greet?.();            // greet이 없으면 호출 안 함 → undefined

// 대괄호 접근
const key = "name";
user?.[key];               // undefined

// 배열
const first = arr?.[0];
```

> **주의**: 아래 세 가지는 자주 하는 실수다.

- `?.`는 **왼쪽 값만** 검사한다. `a?.b.c`에서 `a.b`가 `undefined`이면 `.c`에서 에러가 난다.
- 할당의 왼쪽에는 쓸 수 없다: `user?.name = "x"`는 SyntaxError.
- 남용하면 "있어야 할 값이 없는" 버그를 숨긴다. 진짜 optional 한 값에만 쓰자.

## Nullish Coalescing `??` (ES2020)

> **비유**: `||`는 "통장 잔고가 **0원이면** 계좌가 없는 걸로 치고 기본 계좌 사용", `??`는 "계좌가 **정말 없을 때만** 기본 계좌 사용". 잔고 0원도 엄연히 존재하는 계좌다.

왼쪽이 `null` 또는 `undefined`일 때**만** 오른쪽 값을 사용한다.

```js
const count = 0;

count || 10; // 10   ← 0이 falsy라서 기본값으로 덮어씀 (버그!)
count ?? 10; // 0    ← 0은 null/undefined가 아니므로 유지
```

### `??` vs `||` 비교

| 왼쪽 값 | `a \|\| "기본"` | `a ?? "기본"` |
| --- | --- | --- |
| `undefined` | `"기본"` | `"기본"` |
| `null` | `"기본"` | `"기본"` |
| `0` | `"기본"` | `0` |
| `""` (빈 문자열) | `"기본"` | `""` |
| `false` | `"기본"` | `false` |
| `NaN` | `"기본"` | `NaN` |
| `"hello"` | `"hello"` | `"hello"` |

> **포인트**: `0`, `""`, `false`가 의미 있는 값이라면(수량, 입력값, 설정 플래그) `||` 대신 `??`를 써야 한다.

> **주의**: `??`는 괄호 없이 `||`, `&&`와 섞어 쓸 수 없다.

```js
a || b ?? c;    // SyntaxError
(a || b) ?? c;  // OK
```

## 논리 할당 연산자 `??=` `||=` `&&=` (ES2021)

> **비유**: "빈 화분에만 씨앗 심기". 이미 뭔가 자라고 있는 화분(값이 있는 변수)은 건드리지 않는다.

| 연산자 | 의미 | 동등한 코드 |
| --- | --- | --- |
| `a ??= b` | a가 nullish면 b 할당 | `a ?? (a = b)` |
| `a \|\|= b` | a가 falsy면 b 할당 | `a \|\| (a = b)` |
| `a &&= b` | a가 truthy면 b 할당 | `a && (a = b)` |

```js
const options = { retries: 0, timeout: null };

options.retries ??= 3;  // 0 유지
options.timeout ??= 5000; // 5000

let title = "";
title ||= "제목 없음";    // "제목 없음"

let user = { name: "kim" };
user &&= { ...user, loggedIn: true }; // user가 있을 때만 갱신

// 캐시 패턴
const cache = {};
function getData(key) {
  return (cache[key] ??= expensiveCompute(key));
}
```

`a = a ?? b`와 달리 short-circuit 되므로 a가 이미 값이 있으면 **할당 자체가 일어나지 않는다** (setter 호출 안 됨).

## 구조분해 / 기본값 / rest / spread

> **비유**: 구조분해는 **택배 상자에서 필요한 물건만 꺼내 이름표를 붙이는 것**, rest는 "나머지는 이 봉투에 몽땅", spread는 **상자를 뒤집어 내용물을 새 상자에 쏟아붓는 것**이다.

### 객체 구조분해

```js
const user = { id: 1, name: "Kim", role: undefined, meta: { age: 30 } };

const { name, role = "guest" } = user;    // 기본값은 undefined일 때만 적용
const { id: userId } = user;              // 이름 바꾸기
const { meta: { age } } = user;           // 중첩 구조분해
const { id, ...rest } = user;             // rest: { name, role, meta }

console.log(role);   // "guest"
console.log(userId); // 1
console.log(age);    // 30
```

### 배열 구조분해

```js
const [first, , third = "기본"] = ["a", "b"];
// first = "a", third = "기본"

const [head, ...tail] = [1, 2, 3, 4];
// head = 1, tail = [2, 3, 4]

// swap
let x = 1, y = 2;
[x, y] = [y, x];
```

### 함수 매개변수

```js
function createUser({ name, role = "user", ...extra } = {}) {
  return { name, role, extra };
}

createUser({ name: "Lee", age: 20 });
// { name: 'Lee', role: 'user', extra: { age: 20 } }
createUser(); // 기본값 = {} 덕분에 에러 없음
```

### spread

```js
const merged = { ...defaults, ...userOptions }; // 뒤의 값이 우선
const copy = [...arr, 4, 5];
Math.max(...[1, 5, 3]); // 5
```

> **주의**: spread는 **얕은 복사(shallow copy)** 다. 중첩 객체는 참조가 공유된다. 깊은 복사는 `structuredClone`을 쓰자.

## Array 메서드

> **비유**: 배열 메서드는 공장 라인의 기계들이다. `map`은 **가공기**(모양 바꾸기), `filter`는 **선별기**(불량 걸러내기), `reduce`는 **포장기**(여러 개를 하나로 합치기), `find`는 **검수원**(조건 맞는 첫 번째 하나 집기).

### 기본 고차 함수

```js
const nums = [1, 2, 3, 4, 5];

nums.map((n) => n * 2);              // [2, 4, 6, 8, 10]
nums.filter((n) => n % 2 === 0);     // [2, 4]
nums.reduce((acc, n) => acc + n, 0); // 15
nums.find((n) => n > 2);             // 3
nums.findIndex((n) => n > 2);        // 2
nums.findLast((n) => n % 2 === 1);   // 5   (ES2023, 뒤에서부터 탐색)
nums.findLastIndex((n) => n < 3);    // 1
nums.some((n) => n > 4);             // true  (하나라도)
nums.every((n) => n > 0);            // true  (전부)
nums.includes(3);                    // true
```

`includes`는 `indexOf`와 달리 `NaN`도 찾는다.

```js
[NaN].indexOf(NaN);  // -1
[NaN].includes(NaN); // true
```

### flat / flatMap

```js
[1, [2, [3, [4]]]].flat();         // [1, 2, [3, [4]]]
[1, [2, [3, [4]]]].flat(Infinity); // [1, 2, 3, 4]

const sentences = ["hello world", "foo bar"];
sentences.flatMap((s) => s.split(" ")); // ['hello', 'world', 'foo', 'bar']

// flatMap으로 filter + map 한 번에
[1, 2, 3, 4].flatMap((n) => (n % 2 ? [] : [n * 10])); // [20, 40]
```

### at (ES2022)

음수 인덱스로 뒤에서부터 접근한다.

```js
const arr = ["a", "b", "c"];
arr[arr.length - 1]; // "c" (예전 방식)
arr.at(-1);          // "c"
arr.at(-2);          // "b"
"hello".at(-1);      // "o" (문자열도 지원)
```

### ES2023 비파괴(non-mutating) 메서드

> **비유**: 원본 사진을 직접 포토샵으로 덮어쓰는 것(`sort`)과 **사본을 만들어 편집하는 것**(`toSorted`)의 차이. 원본 앨범(React state)은 그대로 남는다.

기존 `sort`, `reverse`, `splice`는 **원본을 변경**한다. React 상태처럼 불변성이 중요한 곳에서 실수하기 쉬웠다. ES2023에서 복사본을 반환하는 버전이 추가됐다.

| 원본 변경 (mutating) | 복사본 반환 (ES2023) |
| --- | --- |
| `arr.sort()` | `arr.toSorted()` |
| `arr.reverse()` | `arr.toReversed()` |
| `arr.splice(i, n, ...items)` | `arr.toSpliced(i, n, ...items)` |
| `arr[i] = v` | `arr.with(i, v)` |

```js
const scores = [30, 10, 20];

const sorted = scores.toSorted((a, b) => a - b);
console.log(sorted); // [10, 20, 30]
console.log(scores); // [30, 10, 20]  ← 원본 유지

scores.toReversed();        // [20, 10, 30]
scores.toSpliced(1, 1);     // [30, 20]
scores.with(0, 99);         // [99, 10, 20]

// React 상태 업데이트
setTodos((prev) => prev.with(index, { ...prev[index], done: true }));
```

### Array.from

이터러블이나 유사 배열을 배열로 만든다. 두 번째 인자로 map 함수를 받는다.

```js
Array.from("abc");                         // ['a', 'b', 'c']
Array.from(new Set([1, 1, 2]));            // [1, 2]
Array.from({ length: 3 }, (_, i) => i * 2); // [0, 2, 4]
Array.from(document.querySelectorAll("li")); // NodeList → Array
```

### Object.groupBy / Map.groupBy (ES2024)

```js
const people = [
  { name: "A", team: "fe" },
  { name: "B", team: "be" },
  { name: "C", team: "fe" },
];

const byTeam = Object.groupBy(people, (p) => p.team);
// {
//   fe: [{ name: 'A', team: 'fe' }, { name: 'C', team: 'fe' }],
//   be: [{ name: 'B', team: 'be' }]
// }

// 키가 객체이거나 문자열이 아닐 때는 Map.groupBy
const byAdult = Map.groupBy(users, (u) => u.age >= 20);
byAdult.get(true);  // 성인 목록
byAdult.get(false); // 미성년 목록
```

> **주의**: `Array.prototype.groupBy`가 아니라 `Object.groupBy(arr, fn)` 형태의 **정적 메서드**다 (웹 호환성 문제로 바뀌었다). 또 `Object.groupBy`의 결과는 프로토타입이 없는 객체(null-prototype)다.

## Object.entries / fromEntries

> **비유**: 객체를 잠깐 **분해해서 컨베이어 벨트(배열)에 올리고**, `map` / `filter` 기계를 통과시킨 뒤 **다시 조립**하는 것.

객체 ↔ `[key, value]` 배열 변환. 둘을 조합하면 객체에 map/filter를 쓸 수 있다.

```js
const prices = { apple: 1000, banana: 500, cherry: 3000 };

Object.entries(prices);
// [['apple', 1000], ['banana', 500], ['cherry', 3000]]

// 객체 값 변환
const discounted = Object.fromEntries(
  Object.entries(prices).map(([k, v]) => [k, v * 0.9])
);
// { apple: 900, banana: 450, cherry: 2700 }

// 객체 필터링
const expensive = Object.fromEntries(
  Object.entries(prices).filter(([, v]) => v >= 1000)
);
// { apple: 1000, cherry: 3000 }

// Map ↔ Object, URLSearchParams → Object
Object.fromEntries(new Map([["a", 1]]));                 // { a: 1 }
Object.fromEntries(new URLSearchParams("q=js&page=2"));  // { q: 'js', page: '2' }
```

## structuredClone

> **비유**: spread가 "집 주소만 복사한 명함"이라면 `structuredClone`은 **집을 통째로 복제**하는 것. 복제한 집의 가구를 옮겨도 원래 집은 그대로다.

브라우저와 Node 17+에 내장된 **깊은 복사** 함수.

```js
const original = {
  date: new Date(),
  map: new Map([["k", 1]]),
  nested: { arr: [1, 2] },
};
original.self = original; // 순환 참조

const copy = structuredClone(original);
copy.nested.arr.push(3);

console.log(original.nested.arr); // [1, 2] ← 영향 없음
console.log(copy.date instanceof Date); // true
console.log(copy.self === copy);        // true (순환 참조도 처리)
```

| 방법 | Date | Map/Set | 순환 참조 | 함수 |
| --- | --- | --- | --- | --- |
| `JSON.parse(JSON.stringify(x))` | 문자열로 변함 | 빈 객체로 변함 | 에러 | 사라짐 |
| `structuredClone(x)` | 유지 | 유지 | 지원 | `DataCloneError` |

> **주의**: 함수, DOM 노드는 복사할 수 없고(`DataCloneError`), 클래스 인스턴스는 프로토타입이 사라져 **평범한 객체**가 된다(메서드 사용 불가).

여러 줄도 그대로 됩니다.`;

### Tagged Template

> **비유**: 편지를 보내기 전에 **검열관(태그 함수)** 이 먼저 받아서, 고정 문구와 끼워 넣은 값을 따로따로 검사하고 다시 조립해주는 것.

템플릿 앞에 함수를 붙이면 문자열 조각과 값을 분리해서 받는다. styled-components, GraphQL의 `gql`, SQL 라이브러리 등이 이 방식을 쓴다.

```js
function highlight(strings, ...values) {
  return strings.reduce(
    (acc, str, i) => acc + str + (i < values.length ? `[${values[i]}]` : ""),
    ""
  );
}

const item = "커피", price = 4500;
highlight`${item}의 가격은 ${price}원입니다`;
// "[커피]의 가격은 [4500]원입니다"
// strings = ['', '의 가격은 ', '원입니다'], values = ['커피', 4500]

// SQL Injection 방지 패턴 (값을 문자열에 직접 넣지 않고 파라미터로 분리)
const query = sql`SELECT * FROM users WHERE id = ${userId}`;
// → { text: 'SELECT * FROM users WHERE id = $1', values: [userId] }

String.raw`C:\new\folder`; // "C:\\new\\folder" (이스케이프 무시)
```

## 클래스: private 필드와 static block

### Private 필드 `#` (ES2022)

> **비유**: TypeScript의 `private`은 "출입 금지" **안내판**(컴파일러만 지킴), `#`은 **진짜 잠긴 금고**(런타임에서도 열 수 없음)다.

`#`으로 시작하는 필드/메서드는 클래스 외부에서 **문법적으로** 접근할 수 없다. TypeScript의 `private`은 컴파일 타임에만 막지만 `#`은 런타임에서도 진짜 private이다.

```js
class Counter {
  #count = 0;             // private 필드
  static #instances = 0;  // private static

  constructor() {
    Counter.#instances++;
  }

  #log() {                // private 메서드
    console.log(`count: ${this.#count}`);
  }

  increment() {
    this.#count++;
    this.#log();
  }

  get value() {
    return this.#count;
  }

  static isCounter(obj) {
    return #count in obj; // ergonomic brand check
  }
}

const c = new Counter();
c.increment();             // count: 1
c.value;                   // 1
c.#count;                  // SyntaxError
Counter.isCounter(c);      // true
Counter.isCounter({});     // false
```

### Static Initialization Block (ES2022)

> **비유**: 가게 오픈 전 **딱 한 번 하는 개점 준비**. 손님(인스턴스)이 올 때마다가 아니라 가게(클래스)가 문을 열 때 한 번 실행된다.

클래스가 정의될 때 한 번 실행되는 초기화 블록. 복잡한 static 초기화나 try/catch가 필요할 때 쓴다.

```js
class Config {
  static settings;

  static {
    try {
      this.settings = JSON.parse(process.env.APP_CONFIG ?? "{}");
    } catch {
      this.settings = { mode: "default" };
    }
  }
}
```

## 숫자 구분자와 BigInt

### Numeric Separators (ES2021)

```js
const billion = 1_000_000_000;
const hex = 0xff_ff_ff;
const bytes = 0b1010_0001;
console.log(billion); // 1000000000 (값에는 영향 없음)
```

### BigInt (ES2020)

> **비유**: 일반 `Number`는 자릿수가 정해진 **계산기**라서 너무 큰 수는 끝자리가 뭉개진다. `BigInt`는 **종이에 손으로 쓰는 계산**이라 자릿수 제한이 없지만, 소수점은 못 쓴다.

`Number.MAX_SAFE_INTEGER`(2^53 - 1)를 넘는 정수를 정확하게 다룬다.

```js
Number.MAX_SAFE_INTEGER;       // 9007199254740991
9007199254740991 + 2;          // 9007199254740992 (틀림!)
9007199254740991n + 2n;        // 9007199254740993n (정확)

const big = BigInt("12345678901234567890");
typeof big;                    // "bigint"

1n + 1;                        // TypeError: Number와 섞어 쓸 수 없음
1n + BigInt(1);                // 2n
5n / 2n;                       // 2n (소수점 버림)
JSON.stringify({ id: 1n });    // TypeError: 직렬화 불가 → 문자열로 변환해서 전송
```

DB의 `BIGINT` ID, 트위터 스노우플레이크 ID 같은 큰 정수를 다룰 때 유용하다.

> **주의**: `Number`와 섞어 연산할 수 없고 `JSON.stringify`도 실패한다. API로 주고받을 때는 문자열로 변환하자.

## Set 신규 메서드 (ES2025)

> **비유**: 중학교 수학의 **벤 다이어그램**이 그대로 메서드가 됐다. 합집합은 `union`, 교집합은 `intersection`, 차집합은 `difference`.

드디어 집합 연산이 내장됐다.

```js
const fe = new Set(["js", "ts", "react"]);
const be = new Set(["ts", "node", "sql"]);

fe.union(be);               // Set { 'js', 'ts', 'react', 'node', 'sql' }
fe.intersection(be);        // Set { 'ts' }
fe.difference(be);          // Set { 'js', 'react' }
fe.symmetricDifference(be); // Set { 'js', 'react', 'node', 'sql' }

new Set(["ts"]).isSubsetOf(fe);   // true
fe.isSupersetOf(new Set(["js"])); // true
fe.isDisjointFrom(new Set(["go"])); // true (공통 원소 없음)
```

## Promise.withResolvers (ES2024)

> **비유**: 진동벨(promise)과 **진동벨 리모컨**(resolve / reject)을 한 세트로 받는 것. 리모컨을 아무 데나 들고 다니다가 원하는 시점에 누르면 된다.

Promise 바깥에서 resolve/reject를 호출해야 할 때, 예전에는 변수를 밖으로 빼는 보일러플레이트가 필요했다.

```js
// 예전
let resolve, reject;
const promise = new Promise((res, rej) => {
  resolve = res;
  reject = rej;
});

// ES2024
const { promise: p, resolve: res, reject: rej } = Promise.withResolvers();
```

이벤트를 Promise로 감쌀 때 깔끔하다.

```js
function waitForClick(el) {
  const { promise, resolve } = Promise.withResolvers();
  el.addEventListener("click", resolve, { once: true });
  return promise;
}

await waitForClick(button);
console.log("클릭됨!");
```

## 모듈: ESM vs CommonJS

> **비유**: CJS의 `require`는 **필요할 때 그때그때 창고에 가서 물건을 가져오는 것**(실행해봐야 뭘 가져오는지 안다). ESM의 `import`는 **출발 전에 체크리스트로 짐을 미리 싸는 것**(실행 전에 의존성을 알 수 있어 안 쓰는 짐을 뺄 수 있다 = tree-shaking).

```js
// CommonJS (Node.js 전통 방식)
const fs = require("fs");
const { add } = require("./math");
module.exports = { sub };

// ES Modules (표준)
import fs from "fs";
import { add } from "./math.js";
export function sub(a, b) { return a - b; }
export default class Calculator {}
```

| 항목 | CommonJS | ESM |
| --- | --- | --- |
| 문법 | `require` / `module.exports` | `import` / `export` |
| 로딩 | 동기, 런타임에 평가 | 비동기, 정적 분석 가능 |
| Tree-shaking | 어려움 | 가능 |
| top-level await | 불가 | 가능 |
| `__dirname` | 있음 | 없음 → `import.meta.dirname` (Node 20.11+) |
| 바인딩 | 값 복사 | live binding (원본 변경이 반영됨) |
| Node에서 활성화 | 기본값, `.cjs` | `.mjs` 또는 package.json의 `"type": "module"` |

### 동적 import

조건부 / 지연 로딩에 사용한다. Promise를 반환하므로 CommonJS에서도 ESM을 불러올 수 있다.

```js
if (needChart) {
  const { Chart } = await import("./chart.js"); // 코드 스플리팅 포인트
  new Chart(el);
}
```

### live binding 예시

```js
// counter.mjs
export let count = 0;
export function inc() { count++; }

// main.mjs
import { count, inc } from "./counter.mjs";
console.log(count); // 0
inc();
console.log(count); // 1  ← CJS였다면 0
```

## 셀프 체크

**Q1. `const n = 0;`일 때 `n || 10`과 `n ?? 10`의 결과는?**

**A.** `n || 10`은 `10`, `n ?? 10`은 `0`이다. `||`는 falsy인 0을 기본값으로 덮어쓰지만, `??`는 `null` / `undefined`일 때만 기본값을 쓴다.

**Q2. React 상태 배열을 정렬해서 새 상태로 쓰고 싶다. `sort`와 `toSorted` 중 무엇을 써야 하나?**

**A.** `toSorted`다. `sort`는 원본 배열을 직접 바꿔 기존 state를 변형시키므로 불변성이 깨지고 리렌더링이 누락될 수 있다. `toSorted`는 정렬된 새 배열을 반환한다.

**Q3. `const copy = { ...user }` 후 `copy.address.city = "부산"`을 하면 `user.address.city`는?**

**A.** 같이 "부산"으로 바뀐다. spread는 얕은 복사라서 중첩 객체 `address`는 같은 참조를 공유한다. 깊은 복사가 필요하면 `structuredClone(user)`를 쓴다.

**Q4. TypeScript의 `private`과 JS의 `#private`의 차이는?**

**A.** TS `private`은 컴파일 타임 검사일 뿐이라 JS로 변환된 뒤에는 외부에서 접근할 수 있다. `#private`은 언어 차원의 기능이라 런타임에서도 외부 접근이 SyntaxError로 막힌다.

**Q5. ESM이 CJS보다 tree-shaking에 유리한 이유는?**

**A.** ESM의 `import` / `export`는 파일 최상위에 고정된 정적 구문이라, 코드를 실행하지 않고도 번들러가 어떤 export가 쓰이는지 분석할 수 있다. CJS의 `require`는 조건문 안에서도 호출 가능한 런타임 함수라 정적 분석이 어렵다.

## 핵심 정리

- `?.`는 nullish일 때 short-circuit 해서 `undefined`를 반환하고, `??`는 nullish일 때만 기본값을 쓴다. `0`, `""`, `false`를 지켜야 하면 `||` 대신 `??`.
- `??=`, `||=`, `&&=`는 조건부 할당이며, 조건이 안 맞으면 할당 자체가 일어나지 않는다.
- 구조분해 기본값은 `undefined`일 때만 적용되고, spread는 얕은 복사다.
- `at(-1)`, `findLast`, `flatMap`, `includes`(NaN 탐지)를 적극 활용하자.
- ES2023 `toSorted` / `toReversed` / `toSpliced` / `with`는 원본을 바꾸지 않아 불변 상태 관리에 적합하다.
- `Object.groupBy` / `Map.groupBy`는 정적 메서드, `Object.entries` + `fromEntries`로 객체를 배열처럼 가공한다.
- 깊은 복사는 `structuredClone` (Date, Map, 순환 참조 OK / 함수 불가).
- Tagged template은 문자열 조각과 값을 분리해 받아 SQL, CSS-in-JS 등에 쓰인다.
- `#private`는 런타임까지 보장되는 진짜 private이고, `static` 블록으로 클래스 초기화 로직을 묶는다.
- 큰 정수는 `BigInt`(Number와 혼용 불가), 긴 숫자는 `1_000_000`으로 가독성 확보.
- Set에 `union` / `intersection` / `difference`가 생겼고, `Promise.withResolvers`로 외부 resolve 패턴이 간결해졌다.
- ESM은 정적 구조라 tree-shaking과 top-level await가 가능하고, live binding을 제공한다.
